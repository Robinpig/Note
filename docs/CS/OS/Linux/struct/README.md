## Introduction

内核不能依赖 C 标准库，`libc` 里那些现成的容器一个都用不上；更要紧的是，通用容器库的设计目标（把元素装进容器）与内核的需求正好相反——内核需要的是**把一个对象同时挂进多条链、且不为此多花一次内存分配**。这两条约束决定了内核的容器全部是**侵入式（intrusive）**的：链表节点嵌在业务结构体内部，由业务代码自己持有，容器只提供操作函数。

最典型的体现是 `struct list_head` 只有两个指针，它出现在 `task_struct`、`inode`、`struct page` 等几乎每一类核心对象里。一个对象因此可以同时属于多个集合——比如一个进程既在它所在 CPU 的运行队列里，又在自己父进程的 children 链上——而代价只是多嵌一个 16 字节的成员。从成员反推到宿主靠 `container_of()`，这是内核里最常被使用、也最容易被写错的宏之一。

本目录收的都是这类**贯穿全内核的基础设施**：它们不属于任何子系统，但每个子系统都在用。选型时要问的不是"哪种更快"，而是"这个场景能不能加锁、索引是稀疏还是稠密、需不需要 O(1) 取尾"。

## 链表家族：从 list 到 llist

[list](/docs/CS/OS/Linux/struct/list.md) 是默认选择：**双向循环**链表，head 节点的 `prev` 指向尾元素，因此头插、尾插、取首、取尾都是 O(1)。绝大多数"挂一串东西然后遍历"的场景用它就对了。遍历推荐使用 `list_for_each_entry` 这类宏——它把 `container_of` 藏进循环里，让人不必手写指针运算。

[hlist](/docs/CS/OS/Linux/struct/hlist.md) 是**哈希桶专用**的变体。哈希表里桶头数量多、每个桶却常常只有一两个元素，为此维护双向循环的两个指针不划算，`hlist_head` 因此只保留一个 `first` 指针（桶头省一半内存）。它的巧思在 `hlist_node.pprev`——存的不是"前一个节点"，而是"**前一个节点（或桶头）的 next 字段的地址**"。正因为持有的是字段地址而非节点地址，删除首元素时无需特判"要不要改桶头"，一句 `*(n->pprev) = n->next` 对所有位置都成立。

[struct](/docs/CS/OS/Linux/struct/struct.md) 记录的是 **llist**（无锁单链表）。它解决的是"**不能加锁的上下文里怎么挂链**"：中断上半部需要关掉所有中断，一旦加锁系统就会失去响应，所以那里只能用 `cmpxchg` 做 CAS 的无锁插入。代价是能力受限——`llist_del_first()` 只允许**单个**消费者调用，多个消费者同时删除时只能用 `llist_del_all()` 整体摘除。

> [!NOTE]
>
> `struct.md` 这个文件名的覆盖面远大于它的实际内容（只讲了 llist），是早期沿用下来的名字。本目录的数据结构地图以本页为准。

llist 有三处容易踩的坑，都在该篇展开：`llist_del_first()` 取出的是**最新加入的**那个（头插 LIFO，与其他容器的 FIFO 直觉相反）；**多消费者用 `del_first` 会互踩**（它做的是两段式改 `head->first->next`）；以及它**依赖 `CONFIG_ARCH_HAVE_NMI_SAFE_CMPXCHG`**（NMI 可能打断 cmpxchg 中途，所以不能用在 NMI 处理器里）。

## 从链表到索引树

[xarray](/docs/CS/OS/Linux/struct/xarray.md) 换了个思路：它不组织"一串元素"，而是组织**稀疏整数索引 → 指针**的映射，适用场景是文件描述符、inode 号、页缓存的文件偏移这一类"键是整数、空间极其稀疏"的场合。它从 4.20 起引入，用于取代历史上的 radix tree 与 idr 两套实现——把两种用途合并成一套代码。

它的结构是**哈希函数固定的多级树**：只有当某个区间真的放了数据，对应的中间节点才会被分配，这是"稀疏"能省下内存的原因；`xa_node` 里同时维护 `slots` 指针数组与 `tags`/`marks` 位图，让"批量找出带某标记的项"不必遍历全部节点。局部锁（`xa_lock`）而非全局锁，则保证了并发插入的扩展性。页缓存正是它最大的用户，见 [页缓存](/docs/CS/OS/Linux/mm/PageCache.md)。

## 选型速查

| 结构 | 形态 | 关键约束 | 典型场景 |
| --- | --- | --- | --- |
| list_head | 双向循环链表 | 通用，可加锁 | 运行队列、子进程链、设备链 |
| hlist | 单指针头 + 双向节点 | 桶数多、每桶元素少 | 哈希表桶（dentry、netfilter 连接表） |
| llist | 无锁单链表 | 单消费者删除 | 中断上半部、无锁栈 |
| xarray | 多级索引树 | 键为整数且稀疏 | 页缓存、fd 表、inode 索引 |
