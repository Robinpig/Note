## Introduction

过去短暂的互联网历史大致分为两个时期：Web 1.0 与 Web 2.0。

- **Web 1.0（约 1990–2004）**：只读。网站是静态页面，用户消费内容，几乎不参与生产；
- **Web 2.0（2004 年至今）**：可读可写。社交媒体平台让用户生产内容、参与交互，平台通过广告与数据变现；
- **Web 3.0（2014 年提出）**：可读、可写、**可拥有**。用区块链、密码学与代币把数据、身份与资产的所有权交还给用户。

2014 年以太坊推出后不久，联合创始人 Gavin Wood 提出"Web 3.0"的设想。Web3 的核心不是"更快的网页"，而是**把平台对身份、数据和价值的控制权，替换成用户可验证、可携带、可组合的所有权**。

## From Read to Own

Web 2.0 的根本矛盾是：**用户生产内容，平台拥有内容**。平台掌握账号、数据、推荐算法与支付通道，用户离开平台就失去社交关系与作品；平台可以封号、改规则、单方面分成。

Web3 的解法是把"所有权"写进密码学与共识：

- **账号即密钥**：身份不再由平台颁发，而是由私钥控制；
- **资产即代币**：余额、门票、会员资格、积分都是链上可验证的条目；
- **数据可携带**：应用状态公开可读，用户可以把资产与身份带到其他应用；
- **规则可验证**：智能合约的执行逻辑公开，平台不能暗中改规则；
- **可组合**：不同协议可以像积木一样互相调用，形成开放的应用网络。

这不是"去中心化一切"，而是**在关键环节移除单点控制**。Web3 应用仍可能依赖中心化服务器、RPC、前端托管与稳定币发行方，去中心化程度需要逐项评估。

## Core Principles

尽管很难对 Web3 做出严格定义，但它是在几项核心原则的指引下创建的：

- **Web3 是去中心化的**：大部分互联网不是由中心化实体控制和拥有的，而是由构建者和用户分配所有权；
- **Web3 无需许可**：每个人都有参与 Web3 的平等权限，没有人被排除在外；
- **Web3 具有原生支付功能**：它使用加密货币进行线上消费和汇款，而不是依赖传统银行或第三方支付机构过时的基础设施；
- **Web3 去信任**：它通过激励措施和经济机制运转，而不是依赖受信任的第三方。

这些原则是方向而非事实。现实中每条都可以被削弱：排序器可能中心化、前端可能被封锁、治理可能被巨鲸控制、稳定币可能被冻结。**判断一个 Web3 项目，要看去中心化发生在哪一层、信任假设是什么**。

## Identity and Wallets

Web3 的账户体系与 Web2 完全不同：

- **EOA**：一对公私钥，地址即身份，签名即登录；
- **智能账户**：EIP-4337 与 EIP-7702 让账户支持社交恢复、批量交易、代付 gas、权限模块；
- **ENS**：把地址映射成人类可读的名字（`alice.eth`），同时可作为身份与网站入口；
- **SIWE（EIP-4361）**：用钱包签名登录，替代密码与 OAuth；
- **DID / 可验证凭证**：W3C 标准，把身份声明做成可验证、可选择性披露的凭证；
- **声誉与社交图谱**：链上历史、POAP、SBT、Farcaster/Lens 等社交协议。

Web3 身份的最大优势是**可携带与可组合**：同一个地址可以在不同应用间保留资产、声誉与权限。最大劣势是**不可撤销与隐私泄漏**：地址一旦与真实身份关联，全部历史都会暴露；私钥丢失即身份丢失。

## DAOs

DAO（去中心化自治组织）用智能合约管理成员、投票与资金：

- **治理代币**：持有者投票，或委托给代表；
- **金库（treasury）**：多签或治理合约控制资产；
- **提案流程**：论坛讨论 → 链上提案 → 投票 → 时间锁执行；
- **工具**：Snapshot（链下签名投票）、Tally、Aragon、Safe 多签；
- **法律实体**：怀俄明 DAO LLC、马绍尔群岛 DAO LLC 等为 DAO 提供有限法律责任外壳。

DAO 的常见问题：

- **投票率低**：多数代币持有者不参与，治理被少数活跃地址主导；
- **巨鲸与交易所托管**：投票权集中，甚至交易所代客投票；
- **闪电贷治理**：借入代币在单笔交易内通过恶意提案；
- **执行层风险**：提案通过后由多签执行，多签被攻破则治理失效；
- **法律不确定性**：成员责任、税务、证券属性在不同辖区差异巨大。

DAO 不是"没有管理"，而是**把管理规则公开化、可审计化**。它降低了信任成本，但没有消除治理本身。

## DeFi and NFTs

- **DeFi**：借贷、交易、稳定币、衍生品、流动性质押、再质押，用智能合约替代金融中介，见 [Token](/docs/CS/Blockchain/Token.md)；
- **NFT**：数字艺术、收藏品、游戏道具、会员凭证、域名，所有权与版税规则写在合约里；
- **创作者经济**：版税、众筹、粉丝代币、链上分成；
- **游戏**：资产真正归玩家所有，可在不同游戏/市场间流转；
- **RWA**：现实世界资产（国债、房地产、应收账款）代币化，把链下现金流引入链上。

这些应用的共同点是**资产与规则可编程**。风险也同样集中：合约漏洞、预言机操纵、流动性枯竭、监管变化，见 [Security](/docs/CS/Blockchain/Security.md)。

## Infrastructure

Web3 应用依赖一层"链下基础设施"，它们往往比链本身更中心化：

- **RPC 节点**：钱包与 DApp 通过 Infura、Alchemy 等访问链，服务商可限流、审查或记录 IP；
- **索引器**：The Graph 等把链上事件转成可查询 API，是前端数据的主要来源；
- **存储**：IPFS/Filecoin、Arweave 提供内容寻址存储，但"永久存储"仍需付费与激励；
- **预言机**：Chainlink 等把价格、随机数、跨链消息带入链上；
- **Layer 2**：Rollup 提供低费执行，见 [Layer 2](/docs/CS/Blockchain/Layer2.md)；
- **前端托管**：大量 DApp 前端部署在中心化云与 CDN 上，域名或账户被封即无法访问；
- **桥**：跨链资产与消息的主要通道，也是最大风险点。

**"链上去中心化、链下中心化"是 Web3 的常态**。评估一个应用时，应把 RPC、索引器、前端、桥、稳定币发行方都纳入信任模型。

## Limitations

- **用户体验**：助记词、gas、跨链切换、交易确认，门槛远高于 Web2；
- **可扩展性**：L1 吞吐有限，L2 缓解但带来碎片化；
- **隐私**：公链默认公开，地址关联可暴露全部历史；
- **监管**：证券、税务、KYC/AML、制裁合规仍在快速演变；
- **安全**：钓鱼、授权滥用、合约漏洞、桥攻击造成持续损失；
- **投机与叙事**：大量项目以"Web3"包装，实际没有去中心化或真实需求；
- **中心化回潮**：为追求体验，钱包、RPC、排序器、前端重新集中，形成新的中介；
- **可访问性**：网络拥堵时费用高昂，排除低收入用户。

Web3 不是"取代 Web2"，而是**在特定场景（开放金融、数字所有权、跨组织协作）提供一种新的组织方式**。它更适合"需要可验证所有权与无许可组合"的应用，而不是所有互联网产品。

## Evaluation Checklist

判断一个 Web3 项目是否名副其实：

1. **资产与状态是否真的在链上**？还是只有一个数据库加代币？
2. **谁能升级合约**？多签、时间锁、治理，还是单一私钥？
3. **数据是否可用**？用户能否独立重建状态并退出？
4. **排序是否去中心化**？Sequencer 能否审查交易？
5. **前端与 RPC 是否单点**？服务商能否封锁访问？
6. **代币是否有真实用途**？还是纯治理/投机？
7. **治理是否可被少数人控制**？投票权分布如何？
8. **合规与法律结构是否清晰**？用户与成员承担什么责任？
