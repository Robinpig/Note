## Introduction

数据表示回答"有限个二进制位如何编码数值与字符"——它是一切[运算](/docs/CS/CO/arithmetic.md)与[指令](/docs/CS/CO/isa.md)的起点：补码决定了加减法如何统一，IEEE 754 的三段式编码决定了浮点如何对阶与舍入，大小端决定了一个多字节整数在内存里长什么样。本页把组成原理里最容易被"想当然"骗过的编码细节集中讲透：三种有符号编码的取舍、754 的特殊值与舍入模式、ML 时代的低精度格式、大小端与字符编码。

## 整数的机器表示

### 三种有符号编码

| 编码 | 规则 | 表示范围（n 位） | 零 | 加减法 |
|------|------|------------------|-----|--------|
| 原码（sign-magnitude） | 符号位 + 数值位 | $-(2^{n-1}-1) \sim +(2^{n-1}-1)$ | +0 / −0 两个 | 不统一，需分别处理符号 |
| 反码（ones' complement） | 正数同原码，负数按位取反 | $-(2^{n-1}-1) \sim +(2^{n-1}-1)$ | +0 / −0 两个 | 接近统一，有 end-around carry |
| **补码（two's complement）** | 正数同原码，负数取反加一 | $-2^{n-1} \sim +(2^{n-1}-1)$ | **唯一** | **加减统一**，减法 = 加负数 |

现代计算机一律使用补码：减法器可以复用加法器（对减数取反、最低进位置 1），电路最省；硬件只需一套加法通路。代价是范围不对称——8 位下 −128 没有对应的正数，`-(-128)` 溢出后仍是 −128。

- **取负**：$-x = \overline{x} + 1$（按位取反再加一）；
- **符号扩展**：短类型扩到长类型时，有符号数补符号位、无符号数补 0——`char` 到 `int` 的隐式提升走的正是这条路；
- **溢出**：仅对有符号运算发生，判据是最高位进位与进位输出不等（$V = c_{in} \oplus c_{out}$）。

### C 语言的对应陷阱

- **有符号溢出是未定义行为（UB）**：编译器可假设它不发生，基于此做的优化（如 `if (x + 1 < x` 恒为假）会让检查代码失效；无符号回绕反而是定义良好的（模 $2^n$）；
- **整型提升（integer promotion）**：`char`/`short` 先提升为 `int` 再运算，`(char)0xFF + (char)0xFF` 的结果是 510 而不是 −2；
- **有符号数与无符号数比较**：有符号方先被转为无符号，`-1 < 1u` 为**假**——`size_t` 循环里 `i >= 0` 永远成立正是这个坑；
- `char` 是否有符号由实现定义，跨平台代码不要依赖。

## 浮点：IEEE 754-2019

浮点数把一个字切成三段：**符号位 S**（0 正 1 负）、**阶码 E**（biased exponent，实际指数加偏置）、**尾数（有效数）M**（规格化时隐含前导 1，只存小数部分）。

### 基本交换格式

| 格式 | 总位宽 | S / E / 存储尾数 | 阶码偏置 | 备注 |
|------|--------|------------------|----------|------|
| binary16（半精度） | 16 | 1 / 5 / 10 | 15 | 图形与 ML 常用 |
| binary32（单精度） | 32 | 1 / 8 / 23 | 127 | `float` |
| binary64（双精度） | 64 | 1 / 11 / 52 | 1023 | `double` |
| binary128（四精度） | 128 | 1 / 15 / 112 | 16383 | 科学计算 |

754-2019 同时定义了十进制格式（decimal32/64/128），但硬件支持远不及二进制系列。

### 特殊值：阶码全 0 与全 1 的约定

- **E 全 0 且尾数全 0**：±0（`0.0 == -0.0` 为真，但 `1/x` 的符号、`atan2` 等函数可区分两者）；
- **E 全 0 且尾数非 0**：**非规格化数（subnormal）**，按 $(-1)^S \times 0.M \times 2^{1-\text{bias}}$ 解析，把 0 到最小规格数之间均匀填满，保证"最小规格数相减"这类运算平滑下溢而不是一拍子归零；
- **E 全 1 且尾数全 0**：±∞（超出表示范围的上溢结果）；
- **E 全 1 且尾数非 0**：**NaN**（尾数最高位为 1 是 quiet NaN，为 0 是 signaling NaN——后者参与运算会抛异常，可用于标记未初始化内存）；
- 其余编码为规格数：$(-1)^S \times 1.M \times 2^{E-\text{bias}}$。

### 运算五步与舍入

加减乘除的完整步骤（对阶、尾数加减、规格化、舍入、例外处理）见[计算机算术](/docs/CS/CO/arithmetic.md)。754 定义了**五种舍入方向**：

1. **就近舍入、偶数优先（roundTiesToEven）**——默认模式，统计偏差最小；
2. 就近舍入、远离零优先（roundTiesToAway）；
3. 朝 $+\infty$（向上）、4. 朝 $-\infty$（向下）、5. 朝零（截断）——区间算术用。

### 精度陷阱：非结合律

对阶时的右移会丢低位、每次运算都要舍入，因此 $(a + b) + c$ 与 $a + (b + c)$ 可能不同——**浮点加法不满足结合律**。并行规约改变求和顺序即改变结果，这是[并行计算](/docs/CS/OS/Parallel.md)中浮点求和必须小心的根因；消除方式（Kahan 求和、定长归约树）见并行笔记。

### ML 时代的低精度格式（不属于 754 基本格式）

- **bfloat16（BF16，1+8+7）**：截断 binary32 的高 16 位，阶码范围与 FP32 相同、尾数只留 7 位。Google Brain 约 2018 年为 TPU 提出，**不在 IEEE 754-2019 中**，靠"范围优先"避免 FP16 常见的梯度上溢；
- **FP8（E4M3 = 1+4+3，E5M2 = 1+5+2）**：同样不是 754-2019 的基本格式，经 OCP MX 规范与 IEEE P3109 工作组走向标准化；E4M3 重精度、E5M2 重范围，H100 后的 Tensor Core 开始支持；
- **TF32（1+8+10）**：NVIDIA 专有，数据仍按 FP32 存储，Tensor Core 乘加前把输入截到 19 位。

## 检错与纠错编码

前面的编码都假设"存进去什么样，读出来什么样"。真实硬件不满足：宇宙射线翻转电容（**软错误 SEU**，DDR 单 DIMM 每年可累积数百次）、器件老化产生**硬错误**、总线受干扰翻转比特。于是有了在数据位之外附加校验位的整类编码。核心度量是**海明距离（Hamming distance）**：两个合法码字最少有多少位不同。

- 距离 $d$ 的码：可**检测**最多 $d-1$ 位错误，可**纠正**最多 $\lfloor (d-1)/2 \rfloor$ 位错误——纠错要求合法码字之间"足够远"，留出中间态归属；
- **奇偶校验（parity）**：1 个校验位使距离 = 2，检单错、不能定位，错了也只知道"错了"；
- **海明码（SEC）**：$k$ 个校验位按 2 的幂位置交叉放置，可覆盖 $2^k - k - 1$ 个数据位， syndrome（校验结果）直接指出出错位，**纠正单比特错误**；
- **SEC-DED**：再加一个覆盖全部位的奇偶位，距离升到 4——**纠单错、检双错**，是内存子系统的经典配置（如 64 位数据 + 8 位校验的 72 位模）；
- **CRC（循环冗余校验）**：把数据当多项式做模 2 除法，余数作校验位（以太网 CRC-32、存储系统），对**突发错误**检出率极高，但只检不纠，靠上层重传/重读；
- **Reed-Solomon / LDPC**：更强纠错（多位纠错），用于 SSD、光盘、深空通信——超出本页范围，知道它们与海明码同属"距离换可靠"家族即可。

部署层面的分层（on-die ECC / link ECC / chipkill / scrub / MCA-EDAC）见[多处理器内存](/docs/CS/CO/memory.md)的 DRAM 纠错小节，Linux 侧的错误上报见[系统崩溃分析](/docs/CS/OS/Linux/boot/crash.md)。

## 大小端（Endianness）

多字节整数在内存中的字节顺序：

- **小端（little-endian）**：低位字节在低地址（x86、RISC-V 默认、ARM 默认可配）；
- **大端（big-endian）**：高位字节在低地址——**网络字节序即大端**，Socket 编程的 `htonl/ntohl` 系列就是为此存在；RISC-V 也定义了大端变体。

典型陷阱：用 `union` 或指针强转"看"浮点/整数的字节表示（在小端机上看到的字节序与书写顺序相反）、把内存里的结构体直接 `write()` 到网络（跨架构读取即错）、`memcmp` 比较两个数值不同的浮点数。可移植的做法始终是显式移位组装。

## 字符与编码

- **ASCII**：7 位，128 个字符，一切编码的老祖宗；
- **Latin-1（ISO-8859-1）**：8 位单字节，覆盖西欧；
- **Unicode + UTF-8**：码点 21 位，UTF-8 用 1~4 字节变长编码，与 ASCII 完全兼容（ASCII 字符的 UTF-8 编码就是自身）——这是它胜出的关键；
- **UTF-16 / UTF-32**：定宽的 UTF-32 浪费空间；UTF-16 对 ASCII 区字符浪费一半，且历史上有字节序变体（需 BOM 或约定）；
- 中文环境注意：GBK 等本地编码与 UTF-8 混用是乱码的第一来源，跨系统文本一律 UTF-8。
