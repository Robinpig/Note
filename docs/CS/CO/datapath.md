## Introduction

CPU 由两大部分组成：**数据通路（datapath）**——承载数据流动的部件（寄存器堆、ALU、存储器、总线、多路选择器）及其连线；**控制（control）**——根据当前指令产生每个部件的控制信号（"什么时候读寄存器、ALU 做加还是减、结果写回哪里"）。[流水线](/docs/CS/CO/pipeline.md)是数据通路的一种组织方式，而[计算机算术](/docs/CS/CO/arithmetic.md)单元（ALU、乘除法器）就坐落在数据通路之中。本章对比单周期、多周期两种经典数据通路，并剖析"硬布线 vs 微程序"两种控制实现。

## 寄存器堆（Register File）

通用寄存器是数据通路的中枢：典型实现有 **两个读端口 + 一个写端口**（读 RS、RT，写 RD），在一个时钟内可同时读出两个源操作数、并把上一条指令的结果写回。写操作通常在时钟上升沿发生，需配合**转发**避免读-写同址冲突（见[流水线](/docs/CS/CO/pipeline.md)的数据冒险）。

## 单周期数据通路（Single-Cycle）

每条指令都用**一个长时钟周期**走完全部操作：取指 → 译码 → ALU → 访存 → 写回串成一条通路，CPI = 1。

- 优点：控制极简，每条指令行为直观；
- 致命缺点：**时钟周期由最慢指令（如访存或乘法）决定**，一条 `lw` 拖慢整机的 `add`。资源无法复用，面积与功耗浪费严重。

## 多周期数据通路（Multi-Cycle）

把执行拆成**多个较短的时钟周期**，一条指令占若干周期（CPI > 1），但各级功能部件（ALU、寄存器、存储器）**分时复用**，不再为每个指令各建一套硬件：

- 周期长度由"单步操作"而非"整条指令"决定，时钟可显著加快；
- 用少量内部寄存器（如 ALU 输出锁存）在周期之间暂存中间结果；
- 代价是控制更复杂（需状态机决定下一步走哪条微操作路径）。

## 控制：硬布线 vs 微程序

### 硬布线控制（Hardwired）

控制信号由**组合逻辑电路**直接由（操作码 + 当前状态）译出，速度快、无额外存储，但一旦指令集改动就要改电路。RISC 指令规整、控制简单，通常采用硬布线；现代 x86 的前端译码后也走硬布线的乱序引擎。

### 微程序控制（Microprogrammed）

把每条机器指令的"控制步骤"写成**微指令（microinstruction）**，存于**控制存储器（微码 ROM）**；一条机器指令 = 一串微指令序列，由**微程序计数器（µPC）+ 微定序器**驱动。

- 微指令字段常采用"水平/垂直"编码，或用**微操作（µop）**抽象；
- 优点：**改指令集只需改微码**，适合 CISC（x86 的复杂指令、小数端、字符串操作都靠微码实现），也便于修复硬件 bug（微码更新）；
- 代价：多一层存储与取指延迟。历史上曾用微程序实现整个 CPU 控制。

### 现代演变

今天两者边界已模糊：x86 把 CISC 指令**翻译（decode）成内部 µop**，再交给硬布线的乱序执行核心；RISC 也常把少数复杂操作（如乘除法、原子指令）下沉到微码或固件辅助。µop 缓存（µop cache）、分支预测都建立在数据通路之上，详见[流水线](/docs/CS/CO/pipeline.md)。

## 现代数据通路：从顺序到乱序

单周期 / 多周期是教学模型；当代高性能核的数据通路是**乱序（out-of-order）**组织，与[流水线](/docs/CS/CO/pipeline.md)的高级形态配合，把"一条指令串行走完"变成"多条指令在不同部件间并行推进"：

- **前端**：取指 + 译码。x86 在此把变长 CISC 指令切成内部 µop，µop cache 缓存已译码结果直送后端（见[指令系统与 ISA](/docs/CS/CO/isa.md)）；
- **寄存器重命名**：用物理寄存器堆替换架构寄存器的写目标，消除 WAR/WAW 假依赖——Tomasulo 思想的工程化；
- **保留站 / 调度队列**：µop 在此等待操作数就绪，被发射到空闲的执行端口；
- **执行端口**：多个并行的 ALU / AGU（地址生成单元）/ FPU / 访存单元，端口数与发射宽度决定每周期能力（超标量）；
- **ROB（reorder buffer）**：乱序执行、顺序退休的保证，也是精确异常的提交点；
- **存储子系统接口**：store 先进 store buffer 再入缓存，load 要能越过它从缓存/内存取数——store buffer 与 invalidate queue 是[缓存一致性与内存序](/docs/CS/CO/coherence.md)的两大主角。

部件增多的代价是控制复杂度爆炸：每个端口都要调度、每个缓冲都要管理占用，功耗与验证成本随发射宽度非线性上升——这也是近年 CPU 转向"宽而浅"与大小核分工的原因。

## 动态调度算法：记分牌与 Tomasulo

乱序数据通路不是一天长成的，它的算法原型有两个，且今天仍在教科书里考。

### 记分牌（Scoreboard，CDC 6600，1963）

用三张表把"谁在等谁"记在明处：**指令状态表**（每条指令处于发射 ISSUE → 读操作数 READ → 执行 EXEC → 写回 WRITE 四阶段之一）、**功能单元状态表**（忙闲、目的寄存器）、**结果寄存器状态表**（哪个单元将写哪个寄存器）。发射规则全部由组合逻辑查表得出，无需集中控制。

致命短板是**反相关（WAR）必须停顿**：一条 `add $1` 还没读旧值，后一条 `sub $1` 就不能发射——记分牌只会等，不会改名。这限制了可开发的并行度。

### Tomasulo（IBM System/360 Model 91，1967）

Tomasulo 用三件套解决了反相关：

1. **保留站（Reservation Station）**：每条译码后的指令带着操作数（或"等哪个标签"）在此排队，源操作数齐了才发射到执行单元——RAW 相关由硬件自动等待，无需软件/编译器操心；
2. **公共数据总线（CDB）**：执行单元算完后把结果连同**标签**广播到总线，所有等待该标签的保留站同时取走——结果 forwarding 的集中化；
3. **寄存器标签重命名**：目的寄存器写入时分配新标签，后来的指令引用它时拿到的是新标签而非旧值——**WAR/WAW 假依赖就此消失**，只保留真正的 RAW 数据流依赖。

Tomasulo 的局限同样出名：load/store 不走保留站，**内存访问不重排**（后来的乱序机里 load 越过 store 是常态）；以及顺序完成，无法直接支持精确异常。现代乱序核 = Tomasulo 的保留站思想 + 更大的物理寄存器堆（重命名）+ ROB（顺序退休）。

### 现代实现：物理寄存器堆与 ROB

- 重命名表把**架构寄存器**（ISA 可见的几十个）映射到**物理寄存器**（上百到几百个），提交（retire）时才回收旧映射；
- 每周期重命名多条 µop、发射到多个端口；**发射宽度**（4–6/周期）与 **ROB 深度**（两三百项）共同构成 ILP 的物理上限——窗口里找不到可并行的指令，再宽的核也闲着；
- **内存级并行（MLP）**：与 ILP 并列的另一乘数。一个核可同时维持 10+ 个 outstanding cache miss，靠[非阻塞缓存](/docs/CS/CO/Cache.md)把长延迟摊掉——MLP 高的负载（指针追逐除外）在深缓存前更抗打；
- **内存消歧（memory disambiguation）**：load 能否越过先前的 store？硬件推测性地允许（预测"地址不冲突"），错了再回滚。它既是性能利器（store-load 链上插入大量并行），也是 Spectre 类瞬态执行问题的土壤，见[流水线](/docs/CS/CO/pipeline.md)。
