## Introduction

线段树是一种用于高效处理区间查询和区间修改的二叉树结构。它将一个区间不断二分，每个节点管理一个区间，叶子节点对应单个元素，内部节点则代表其子区间的合并结果。
线段树可以在 $O(logn)$ 的时间复杂度内实现单点修改、区间修改、区间查询（区间求和，求区间最大值，求区间最小值)等操作

线段树将每个长度不为 1 的区间划分成左右两个区间递归求解，把整个线段划分为一个树形结构，通过合并左右两区间信息来求得该区间的信息．这种数据结构可以方便的进行大部分的区间操作

### Building the Tree
线段树是**固定的二叉树**：给定 $n$ 个元素，把 $[1, n]$ 递归二分（$[l, r]$ 拆成 $[l, mid]$ 与 $[mid+1, r]$，$mid = \lfloor (l+r)/2 \rfloor$），直到 $l = r$，就得到 $n$ 个叶子与 $n-1$ 个内部节点。

节点的信息有两种装法：

- 叶子节点 $l = r$：直接装该位置的元素值$a_l$。
- 内部节点：装两个子节点的**聚合结果**，聚合算子由题目决定（求和是 `+`，最小值是 `min`，最大质因数是 `gcd`……）。

关键性质：树高为 $\lceil \log_2 n \rceil$，所以任一叶子到根的路径只有 $O(\log n)$ 步 —— 这是所有 $O(\log n)$ 复杂度的来源。

**存储方式**。最常用的是用数组模拟这棵二叉树，开`4n` 空间：因为按 `p` 号节点派生出 `2p`（左子）、`2p+1`（右子），递归时把区间一起往下传，无需显式存左右儿子指针。

```java
// 区间求和：arr 为 0-indexed，线段树内部用 1-indexed 下标
int[] tree;
int n;

void build(int p, int l, int r, int[] arr) {
    if (l == r) { tree[p] = arr[l - 1]; return; }
    int mid = (l + r) >>> 1;
    build(p * 2, l, mid, arr);
    build(p * 2 + 1, mid + 1, r, arr);
    tree[p] = tree[p * 2] + tree[p * 2 + 1];
}
```

**离散化**。当下标范围巨大时（例如按时间戳、按坐标建树，值域到 $10^9$），不可能开 $4n$ 数组。此时先**坐标压缩**：把所有实际出现过的下标排序去重，映射成 $1 \dots m$ 的连续编号，在压缩后的下标上建树，$m$ 只等于有效元素个数。注意离散化后**丢失了原始距离信息**，因此「区间长度」「按实际坐标求距离」这类操作不能再从下标直接得出，必须另外记录原值。数组的存储细节见 [array](/docs/CS/Algorithms/struct/array.md)。

另一个选择是**动态开点线段树**：只在需要访问的区间上真正创建节点，用不到的儿子指针留空。适用于「值域极大但实际修改点很少」的场景，空间从 $O(n)$ 降到 $O(m \log n)$（$m$ 为操作数）。

### Lazy Propagation
纯递归做区间修改是 $O(n)$：区间 $[l,r]$ 被拆成 $O(n)$ 个节点都要改。懒标记的思路是：**只在路径上打标记，推迟到一个节点真正需要向下访问时才下推（push down）**。

每个节点额外挂一个 `lazy` 字段，表示"我已经整体作用到这个区间上，但孩子们还不知道"。访问子节点前必须先 `pushDown`，让标记下沉一层。

标记有两个关键约束：

**一是标记必须能 O(1) 地更新当前节点的聚合值**。例如区间加 $v$：若节点维护的是区间和 `sum`，则 `sum += v * 区间长度`，因为每个元素都加了 $v$。这不是所有聚合算子都成立的 —— 区间加对区间最大值也成立（`max += v`），但区间加对"最大公约数"就不成立。

**二是标记会复合，必须定义清楚合并顺序**。这是最容易写错的地方：

| 标记 | 语义 | 复合规则 |
| --- | --- | --- |
| `add`（区间加） | 区间内每个元素 $+= v$ | 加法可交换可结合，新 `add` 直接累加 |
| `set`（区间赋值） | 区间内每个元素 $= v$ | 赋值**覆盖一切**，新 `set` 会抹掉旧的 `add` |

下推顺序**必须先 `set` 后 `add`**：

- 若先 `add` 后 `set`，旧的加法被赋值覆盖，语义错误 —— 你本想让"先加 5 再赋 10"，结果变成"赋 10"，加的 5 消失了。
- 若先 `set` 后 `add`，语义正确 —— 先把整个区间刷成 $v$，再加上累加量。

同理，在 `set` 发生时必须把 `add` **清零**（不是累加），因为赋值之前的加法已被覆盖：

```java
// 区间赋值
void applySet(int p, int l, int r, int v) {
    tree[p] = (long) v * (r - l + 1);   // 假设维护区间和
    set[p] = v;                         // 记住赋值
    add[p] = 0;                         // 赋值覆盖此前所有加法，必须清零
}

// 区间加
void applyAdd(int p, int l, int r, int v) {
    tree[p] += (long) v * (r - l + 1);
    add[p] += v;                        // 若 set[p] 有效，也可折算进 set[p]
}

void pushDown(int p, int l, int r) {
    int mid = (l + r) >>> 1;
    if (set[p] != NO_TAG) {            // 先下推赋值
        applySet(p * 2, l, mid, set[p]);
        applySet(p * 2 + 1, mid + 1, r, set[p]);
        set[p] = NO_TAG;
    }
    if (add[p] != 0) {                 // 再下推加法
        applyAdd(p * 2, l, mid, add[p]);
        applyAdd(p * 2 + 1, mid + 1, r, add[p]);
        add[p] = 0;
    }
}
```

调用 `pushDown` 后要**及时清掉父节点的标记**，否则会重复作用。

### Common Maintained Information
| 维护信息 | 合并算子 | 能否带懒标记 |
| --- | --- | --- |
| 区间和 | `sum = L + R` | 区间和、区间赋值都行 |
| 区间最值| `max = max(L, R)`、`min = min(L, R)` | 区间加、区间赋值都行（`max += v` 对加法成立） |
| 区间 GCD | `gcd = gcd(L, R)` | **只能区间赋值，不能区间加** |
| 矩阵乘积 | `mat = L × R`（有顺序） | 取决于矩阵元素类型，一般只能单点改 |

**区间 GCD 为什么特殊**：`gcd` 是**不可逆**的 —— 知道 $\gcd(a,b)$ 无法反推 $a, b$，所以不存在"区间加的逆操作"。加法有逆操作（减法），这正是差分数组 + 树状数组能处理区间修改的原因；而 $\gcd$ 没有逆操作，差分就失效了。这是线段树相对[树状数组](/docs/CS/Algorithms/struct/Fenwick-Tree.md)的核心优势所在。

**矩阵乘积**。稠密矩阵的区间乘积可以直接存进线段树：叶子存单个矩阵，内部节点存 `左儿子 × 右儿子`。注意矩阵乘**不可交换**，所以合并顺序必须是固定的 `L × R`，不能像区间和那样随意交换左右。典型用途是加速斐波那契数列、矩阵求逆、行列式等递推问题。

### Complexity
| 操作 | 复杂度 |
| --- | --- |
| 建树 | $O(n)$ |
| 单点修改 | $O(\log n)$ |
| 区间查询 | $O(\log n)$ |
| 区间修改（带懒标记） | $O(\log n)$ |
| 空间 | $O(n)$ |

区间操作之所以仍是 $O(\log n)$ 而非 $O(\log^2 n)$：虽然一个区间会被拆成 $O(\log n)$ 个节点，但被完整覆盖的节点**直接返回、不再递归**，只有两条边界路径上的节点继续向下，每条路径长 $O(\log n)$。

**与树状数组（Fenwick Tree）的对比**。

| 维度 | 线段树 | 树状数组 |
| --- | --- | --- |
| 可维护的信息 | 任何可结合的聚合（和、最值、GCD、矩阵） | 只支持**可逆**的"前缀减 / 前缀和"类操作 |
| 常数与代码量 | 较大，$4n$ 空间 + 递归 + 懒标记 | 很小，约 10 行，$O(n)$ 空间 |
| 区间修改 | 直接支持 | 需借助差分（且算子须可逆） |
| 典型选型 | 有懒标记、区间最值、GCD 等需求时 | 只做点改 + 区间和 / 计数 / 逆序对 |

选择依据很直接：只需要「点改 + 区间和」就用树状数组，常数小得多；一旦需要**不可逆**的运算（区间 GCD）或区间懒更新，线段树是唯一稳妥的选择。

### Relation to BST
线段树本质是**按值域/区间固定划分的二叉树**，与普通二叉树（如 [Binary Tree](/docs/CS/Algorithms/tree/Binary-Tree.md)）的共同点是"每个内部节点由两个子节点合并而来"，区别在划分依据：

| 维度 | 线段树 | 搜索树（BST） |
| --- | --- | --- |
| 划分依据 | **位置**（中点） | **值的大小关系**（左小右大） |
| 形状 | 完全确定，由 $n$ 唯一决定，无需平衡 | 由插入顺序决定，可能退化成链 |
| 中序遍历 | 等于原序列顺序 | 等于升序 |
| 查找 | 按下标定位，不比较元素值 | 依赖比较语义 |

关键结论：线段树**不需要任何平衡操作**（AVL、红黑树的旋转一概用不上），因为它从构造上就是满的、平衡的。代价是它只认下标，无法按值查找 —— 需要按值检索时得先二分找下标，或改用 BST 类结构。

### Variants
- **动态开点线段树**：只在访问到的区间上创建节点，值域极大但有效操作点很少时用，空间 $O(m \log n)$。
- **主席树（可持久化线段树）**：每次修改只复制路径上的 $O(\log n)$ 个节点、其余与旧版本共享，从而保留全部历史版本；由此可回答「区间第 $k$ 小」这类离线查询。
- **树链剖分 + 线段树**：先用 Heavy-Light 把树上的一条路径拆成 $O(\log n)$ 段连续区间，再落到线段树上做路径聚合与路径修改，是树上问题（如树上路径求和）的标准组合拳。
