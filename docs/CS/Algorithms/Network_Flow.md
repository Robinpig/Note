## Introduction

**网络流**（network flow）是图论中抽象能力最强的一支：只要问题能被表述成「沿边输送流量、顶点守恒、边有容量上限」，就能先用最大流求解。它把一批看起来毫不相干的问题统一到「求一个最大流」这个子问题之下，而最大流又有成熟的组合算法。

关键价值在于**归约（reduction）**的威力：二分图匹配、最小割、最小费用调度、项目排程、资源分配这类问题的难点不在算法本身，而在「能否建模成流」。一旦建成，求解往往只需调用一个黑箱。

## Definitions
**流网络** $G = (V, E, s, t)$ 由容量网络与源点 $s$、汇点 $t$ 构成。一个**流** $f : E \to \mathbb{R}$ 满足：

- **容量限制**：$0 \le f(u,v) \le c(u,v)$，边 $c(u,v)$ 是容量上限。
- **流量守恒**：对每个中间顶点 $v$，$\sum_{u} f(u,v) = \sum_{w} f(v,w)$。
- **流的总量**：$|f| = \sum_v f(s,v) = \sum_v f(v,t)$。

注意「流的总量」只在源汇处特殊——中间顶点进出相等，所以全图任意割的净流量都等于总流量，这正是最大流最小割定理成立的原因。

**残量网络**（residual network）是流算法的心跳：把每条边的容量分为「已推送量」与「剩余容量」，并为其**反向边赋予相反方向的剩余容量**。反向边的存在使得「撤销一个已做出的推送决策」成为可能——这是单纯贪心无法做到的，也是所有流算法都能「回头修正错误」的根本原因。

```
struct Edge { int to, cap; };  // cap = 剩余容量

addEdge(u, v, cap):
    edges[u].push({v, cap})       // 正向
    edges[v].push({u, 0})         // 反向，初始 0
```

增广路径（augmenting path）指残量网络中从 $s$ 到 $t$ 的一条路径，瓶颈容量为路径上最小剩余容量。沿它推送该容量后，总流量增加同样多。

## Ford-Fulkerson and Augmenting Paths
**增广路定理**：只要残量网络中仍存在 $s \to t$ 的路径，当前流就不是最大流；反之则是。

**Ford–Fulkerson** 因此是朴素的「反复找增广路、推满、删满的边」直到找不到为止。它正确，但效率取决于**选择的增广路序列**——如果每条路都只推 1 个单位（如整数容量为 1 的坏例），可能需要 $O(VE)$ 次增广。

实现上的经典写法用 **DFS 代替 BFS**（即「FFDFS」），也可用 BFS（即 Edmonds–Karp）。这一族统称 **增广路算法**。

## Edmonds-Karp Algorithm
固定用 **BFS** 找增广路。因为 BFS 找到的一定是**边数最少**的增广路，而边数最少意味着单次推送的流量最大（容量为整数时），增广次数被有效压到 $O(VE)$。

**复杂度 $O(VE^2)$**。它常被作为「网络流的标准解法」在竞赛中使用——实现简单（一个 BFS + 增广循环），复杂度足够支撑绝大多数中等规模题目，且正确性直观、无需理解当前弧优化。

## Dinic's Algorithm
Dinic 是**分层 + 阻塞流**的组合，也是工业与竞赛中的首选。

三步：

1. **BFS 分层**：在残量网络中从 $s$ BFS，给每个顶点标层次 `level`，只沿 `level` 递增的边走，建立分层图 `G'`。
2. **DFS 阻塞流**：只在 `G'` 上 DFS 推送流量，用**当前弧优化**（每个顶点记住遍历到第几条邻接边）保证总扫描量线性，直到推不出流为止。
3. 若 $t$ 不可达则结束；否则回到步骤 1。

**复杂度**：最坏 $O(V^2E)$；在所有边容量为 1 的网络（即**单位网络**）上退化更快，达 $O(E\sqrt{V})$。

**当前弧优化**是 Dinic 快于朴素增广路的关键：同一次 DFS 中，一条边若已推满流量就无需重试，记住它扫描到的位置即可把「反复扫无用边」摊销掉。

## Max-Flow Min-Cut Theorem
网络流最重要的定理：

> 任意流的流量 $\le$ 任意割的容量；且**最大流的流量 = 最小割的容量**。

证明是双向的：任意割 $(S, T)$ 的容量正是「从 $S$ 流向 $T$」的总量上限，故 $|f| \le c(S,T)$；而当残量网络中 $s$ 与 $t$ 不再连通时，取 $s$ 所在连通块 $S$，其与外部的边全部推满（否则那条边仍是可用的正向边），于是这个 $S$ 就是一个恰好等于当前流量的割。

**「残留网络反割」**是它的实用形式：算完最大流后，在残量网络中从 $s$ 出发做一次可达性搜索，可达点集即构成一个最小割 $(S, T)$。这意味着**一次最大流同时给出了最优解与最优性的证明**（对偶解），在资源分配类问题中价值很高。

由此可推出著名的**最大容量路径 = 最小容量割**（即全局最小割，MaxFlow-MinCut 的另一面，用 $O(VE)$ 的三次 DFS 求出）。

## Modeling Patterns
从问题到流的翻译词典：

| 问题里的说法 | 流量网络里的对应 |
| :-- | :-- |
| 资源 / 容量上限 | 边的容量 $c(u,v)$ |
| 分配 / 调度 | 推流的流量 |
| 供需 / 平衡约束 | 顶点的流量守恒 |
| 「至少 / 至多」约束 | 建源点边或汇点边的容量 |
| 互斥 / 二选一 | 拆成两条平行边（各自容量上限） |
| 收益 | 最小费用流的费用，见下 |

**典型问题与建模**：

- **二分图最大匹配**：左部顶点连源点（右容量 1），右部顶点连汇点（右容量 1），每条配对边连左→右容量 1。最大流 $= 1$ 的流量即匹配数——这是 [König 定理](/docs/CS/Algorithms/graph/Matching.md) 的另一种证明方式。
- **最小割 / 割性质应用**：把「必须至少跨过的边界」建成最小割，如「最小化删除代价使图分离」。
- **图片/文档分类、AI 的特征归属**：本质是二分图分类，用流求解最小代价二分类。
- **任务排程 / 运输问题**：源→需求点→汇，容量与费用分别对应资源与耗时。

**建模时的两个易错点**：

1. **容量不可随意放大**。若把某条边容量从 1 改成「很大」以求「自由通过」，答案会失真；正确做法是用源/汇边的容量来表达「至多 1」这一约束本身。
2. **必须先验证可行流存在**。若无解，可能是建模断了（少连边），而非真的无解。

## Min-Cost Max-Flow
在流量之上再加权值：边带费用 $w(u,v)$，要求「流量最大的前提下费用最小」。做法是把每条边的**容量设为 1、费用为原费用**，用**反向边的费用取负**来表达「可撤销」，然后在残量网络中沿**最短路（SPFA / Dijkstra）增广**。

它同时解决了两个目标，因此在**带权二分图匹配**（点权转边权）、**最小费用任务分配**、**带收益的资源调度**等场景中比「先算最大流再手工优化」更可靠。逆向负费用的设计与最大流的反向边完全同源——都是「允许撤回决策」的工程手段。
