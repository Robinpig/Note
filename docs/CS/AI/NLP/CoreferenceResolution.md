## Introduction

共指消解（coreference resolution）回答的是阅读理解中最朴素的问题：文中的「他」「它」「这家公司」，到底指谁。它也是自然语言处理里第一个真正意义上的篇章级（discourse-level）任务——单个句子的信息远远不够用，系统必须跨越句界，把散落全文的 mention（提及，指向某个实体的文本片段）归并成实体链（coreference chain），例如把「马云」「他」「该公司创始人」聚成同一条链。在本库的 [NLP](/docs/CS/AI/NLP/NLP.md) 知识地图里，它正是第一个以「整篇文档」为处理单元的任务。

要分清一对常被混用的概念：共指（coreference）判断两个 mention 是否指向同一现实实体，回指（anaphora）判断一个表达是否依赖更早出现的先行语（antecedent）才能被解释。二者大部分重叠——「他」既回指「马云」，也与「马云」共指——但重复指称（先写「马云」、后文再现「马云」）是共指而非回指，因为它不依赖先行语获得语义。本库行文按惯例用「共指消解」统称整个任务。

## Mentions and Entities

形式化地看，共指任务分两步：先找出文中所有 mention，再把这些 mention 划分成互不相交的实体簇。mention 的形态极其多样——代词、专名、描述性名词短语，以及中文、日文中常见的零指代（zero anaphora）：「我买了本书，很喜欢」的后半句省略了主语，读者需要自行回溯补齐。识别这类「有意义的片段」远比词级标注复杂，思路接近 [SequenceTagging](/docs/CS/AI/NLP/SequenceTagging.md) 一类的序列标注与片段抽取。

第二步才是共指区别于其他任务的本质：标注对象不是单个片段，而是片段之间的等价关系。这些关系还带有结构复杂性：mention 可以嵌套（一个专名嵌在更长的名词短语内部），也可能出现桥接（bridging）——「我买了辆车，方向盘是坏的」里「方向盘」并非「车」的同指，却要借助「车」才能被理解。要同时容纳嵌套、桥接与零指代，逐词分类式的框架从一开始就行不通。

工程上 mention 候选通常由 n-gram 枚举产生，数量随文档长度平方增长，真实系统必须用长度上限、频率与句法过滤来剪枝——候选召回与计算效率之间的取舍，贯穿了所有时代的共指系统。

## Why Coreference Is Hard

难度首先来自指代形式的多样：同一实体可以用代词、简称、全称、描述性短语反复登场，字符串层面几乎没有稳定信号。其次，消解依赖语义与常识而非句法——经典的 Winograd Schema 例子：「奖杯放不进行李箱，因为它太大了」，「它」指奖杯；把「太大」换成「太小」，同一个代词的指向就翻转，而两句话的句法结构完全相同，做出区分的是尺寸常识。

第三重困难是距离与竞争：先行语可能在数句乃至数段之外，中间还夹着大量干扰实体。最后，错误会叠加：mention 检测漏掉一个，实体链就出现缺口；聚类错并一步，后续判断都建立在错误事实上。可以说，共指同时考验句法、语义与世界知识，这使它长期是统计方法时代进展最慢的任务之一。

对中文而言难度还要再加一层：零指代与话题优先（topic-prominent）结构高发，主语省略更常见，系统经常要在没有任何显式形式的情况下恢复实体。

## Rule-Based Beginnings

最早的做法把共指当成句法问题。Hobbs 式算法从代词出发，在句法树上按固定遍历顺序搜索候选先行语，先用数一致、性一致等约束过滤，再按最近性、句法角色等偏好排序取最优；显著度（salience）模型则给不同语法角色与位置赋予权重，随句子推进动态更新候选实体的排名。

这类系统可解释，也能针对特定语料手工修补，但规则之间互相牵制，换语言、换领域往往要推倒重来，性能天花板很低。规则退场不是因为思路错误，而是因为它承载不了「语义与常识」这层判断。

它们之间如何比较优劣，还顺带倒逼出了评测：共指很早就有公开标注语料与统一指标，这套评测传统一直延续到今天。

## Statistical Models

统计学习时代的第一步，是把任务降维成一个更小的判别问题。

### Mention-Pair Classifiers

给定两个 mention，判断它们是否同指：特征可以人工设计——字符串与词形重叠、距离、性别与数的兼容性、句法角色、同位语结构等。相比规则，这类分类器鲁棒得多，但埋下两个隐患：训练目标是彼此独立的成对判断，推理时需要的却是全局一致的实体划分；所有 mention 两两配对，计算量随文档长度平方增长。

### Mention-Ranking and Clustering

改进方向是 mention-ranking：不再孤立地判断一对 mention，而是为每个 mention 的全部候选先行语打分排序，取最高分（或超过阈值者）作为前指。打分在候选之间共享，决策一致性明显好转。但成对分数仍要经过聚类策略（逐步合并、best-first 等）才能变成实体链，误差于是在「检测 mention」与「聚类实体」两个环节之间来回传播：检测漏掉的片段永远无法被聚合，聚类阶段的误合并又会污染后继判断。

这种「成对建模、全局使用」的错位，成为神经网络方法直接发力解决的问题。把三代监督模型并排看：

| 建模粒度 | 代表形态 | 主要局限 |
| :--- | :--- | :--- |
| mention-pair | 两个 mention 的二分类 | 决策彼此孤立，难以保证一致 |
| mention-ranking | 单个 mention 的候选前指排序 | 仍是成对视角，聚类另行处理 |
| entity-level | 对实体簇整体打分与划分 | 特征与搜索空间更复杂 |

回头看，这一阶段真正的遗产不是某个模型，而是被定型的概念框架：mention、前指、聚类、评测指标都在此期间成形，神经网络只是换了执行方式。

## Neural Approaches

神经网络阶段的目标很明确：让检测与聚类在同一目标下协同。

三条推进线——端到端、实体级一致性、span 级表示——彼此并不互斥，而是先后叠加在同一套基线上。

### End-to-End Models

Lee 等人 2017 年给出的端到端模型改变了任务形态：用循环网络为每个候选 span 打出「是不是 mention」的分，同时为它计算对所有前指 span 的分，两类分数在同一目标函数中联合训练；推理时只做一次从左到右的贪心合并。检测与聚类第一次被装进同一个网络、同一个损失里，整条管线从「若干模块串联」简化为单一模型。

其后各版本普遍换上更强的上下文编码器，span 表示的质量成为新的控制变量——这也解释了为什么后来的预训练模型最先改进的地方就是 span 级目标。

### Higher-Order Consistency

成对监督还有一个盲点：两个 mention 各自与第三个片段「成对相容」，但它们未必属于同一实体。Higher-order 模型因此把推理抬升到实体层面，用 coarse-to-fine 的注意力机制在整簇范围内反复整合信息，让链内 mention 相互印证、共同修正打分。它想表达的判断标准很清楚：共指的质量取决于整条链的一致性，而不是若干对局部判断之和。

### Span-Level Pretraining

SpanBERT 顺着另一个方向补课：既然共指的输入单位是 span，就把预训练目标从 token 改成 span——掩码连续片段，并强制用片段边界词预测被掩内容，使 span 级表示本身更准确、更稳定。表示变强后直接转化为基准提升，一度刷新 CoNLL-2012 成绩。

两条线合起来说明了同一件事：「任务专用的结构设计」与「更强的通用表示」可以叠加收益，这也是端到端时代之后该任务的主要推动方式。

## The LLM Era

从机制上说，隐式掌握并不意外：自回归语言建模要在长上文下预测下一个词，指代跟踪本就是基本动作之一，模型规模与上下文长度同时上来之后，这项能力自然被隐式习得。

长上下文 LLM 因此对「谁是谁」表现出很强的把握：读完数千 token 的文档后，代词链往往能顺滑跟进，用问答形式直接询问，隐式表现甚至超过不少专门的监督系统。但共指任务的交付物恰恰是显式结构化输出——mention 边界与完整的实体链清单——错位就在这里：模型「懂」不等于能把整篇文档的链一次性、无矛盾地说清楚，链的一致性还会随长度衰减。

工程上的对策主要有三类：

- 分步 prompting：先抽 mention，再逐步归并，最后全局审计；
- 分段处理再拼接：用长窗口消化局部，靠规则或二次模型对齐跨段实体；
- 在长文本标注数据上微调，用监督信号把隐式理解「逼」成稳定结构。

这一节与 [LLM](/docs/CS/AI/LLM/LLM.md) 一章讨论的「隐式能力 vs 显式结构」主题正好互文，共指是观察这对矛盾的一个干净样本。

## Evaluation

共指研究长期共用 OntoNotes 标注体系下的 CoNLL-2012 基准：语料覆盖英文、中文与阿拉伯语，标注了 mention 边界与实体链，模型输出需要与人工链对齐后计分。麻烦在于「对齐」本身没有唯一答案，常用指标因此分成三个家族：

| 指标 | 统计对象 | 主要偏向 |
| :--- | :--- | :--- |
| MUC | 实体链内部的链接 | 偏向大簇，忽略单提及实体 |
| B³ | 每个 mention 的同链伙伴 | mention 加权，大簇影响更大 |
| CEAF | 预测簇与标准簇的最优一对一匹配 | 结果依赖相似度函数与匹配方式 |
| CoNLL 平均 | 三者 F1 的算术平均 | 折衷值，并不消除三者之间的矛盾 |

三个指标对「细分」与「误并」两类错误的惩罚方式不同，结论时常互相打架，CoNLL 平均只是把它们捆在一起；后来还出现过 LEA 等试图更平衡的方案。一个任务需要三个指标才能勉强描述，本身就说明聚类类评估之难——共指的评测思路（对齐、匹配、平均）在 [Evaluation](/docs/CS/AI/NLP/Evaluation.md) 中有更一般的讨论。

还有一个容易被忽视的成本项：实体链是文档级结构，人工标注昂贵，标注者之间的一致性也有限，不同人对同一条链的粗细划分可以有合理差异——模型追逐的其实是一个区间，而不是唯一的正确答案。

## Downstream Impact

共指是文档级信息抽取的隐形前置工序。关系抽取吃的是实体对，如果后文的「他」没有还原为「马云」，「马云 创立 阿里巴巴」与「他卸任」就无法拼进同一条知识图谱条目；共指不直接产出答案，却决定答案的地基是否平整。

长文问答同理：把问题中的指代与文中的实体链对齐，通常是一切的起点。这也解释了为什么共指的得分常被视为「文档理解管线」的基础分——它错了，后面每一步都错，详见 [InformationExtraction](/docs/CS/AI/NLP/InformationExtraction.md)。

## Outlook

从 Hobbs 规则到端到端网络，再到长上下文 LLM，共指的处理形态换了好几代，但篇章一致性始终是最后被攻克的部分：模型在单句内早已近乎完美，一旦进入跨段落的长距离实体追踪，错误便开始累积。

也正因如此，共指是观察「篇章级理解」的标本——检验一个系统是否真的读懂了整篇文章，直接的问法就是让它把「谁是谁」说清楚。
