## Introduction

评估（evaluation）研究的是「怎么知道一个 NLP 系统好不好」。它不是研究流程的收尾环节，而是**决定研究方向的那只手**：「你怎么测量，模型就怎么进化」——BLEU 主导的年代，机器翻译集体优化 n-gram 重叠；榜单时代，模型开始为 GLUE 的分数调参；LLM-as-judge 流行之后，输出又开始向裁判模型的偏好靠拢。指标换一次，整个领域的优化目标就跟着换一次。

各任务篇只留一句自己的专有指标（翻译的 BLEU、摘要的 ROUGE、序列标注的实体级 F1），完整的拆解集中在本篇。它同时是一份避坑指南：每一类指标都有一副自己特有的「说谎方式」，选错指标不只是数字不漂亮，而是会把项目引向错误的方向。

评估可以粗分两类：**外在评估（extrinsic）**看下游任务的实际效果——翻译好不好看人工评分、分类好不好看线上指标；**内在评估（intrinsic）**看模型自身的性质，比如语言模型的困惑度。外在评估贴近真实目标但昂贵、慢；内在评估便宜、可自动化，代价是「内在变好 → 外在变好」这个假设经常不成立。后面每一节讲的指标，本质上都在这个天平上选位置。

## Language Model Perplexity

语言模型最经典的内在指标是**困惑度（perplexity，PPL）**。定义很直接：对一段文本，取模型给出的平均负对数似然，再取指数——

```
PPL = exp( - (1/N) * Σ log P(w_i | w_<i) )
```

直觉有两层：它等于**模型在每一步平均「在多少个候选词之间犹豫」**，也等于文本的平均分支因子。模型给正确词的预测概率越高，困惑度越低，所以**越低越好**。

用的时候必须记住两条边界。第一，**困惑度只在固定词表与固定分词下可比**：换一套分词、词表大小一变，对数似然的基准就变了，两组数字放在一起毫无意义——这也是「不同论文的 PPL 不可直接对比」的原因。第二，**困惑度与下游表现只弱相关**：一个模型可能更会拟合语料分布，却更不会遵循指令、做推理——预训练规模越大，这条裂缝越明显。所以 LLM 时代困惑度基本退居训练监控的辅助位置，能力评估让位给基准与人类判断。

## Generation Metrics

生成任务（翻译、摘要、对话）的评估是 NLP 里最麻烦的一块：输出是开放文本，没有一个标准答案可以逐字比对，「正确答案」往往有几十种写法。自动指标因此全部是**与参考输出的相似度**——只不过程度不同。下表按「比较的粒度」从表层到语义排列：

| 指标 | 比较方式 | 常用场景 | 主要软肋 |
| :--- | :--- | :--- | :--- |
| BLEU | n-gram 精度 + 长度惩罚 | 机器翻译 | 只认字面重叠，同义改写被冤枉 |
| ROUGE | n-gram 召回（含最长公共子序列） | 摘要 | 偏向长输出与照抄原文 |
| METEOR | 对齐 + 同义词、词形，调和平均 | 机器翻译（历史） | 依赖外部词典，工程复杂 |
| chrF | 字符 n-gram 的 F 值 | 形态丰富语言、中文 | 忽略词序与语义 |
| BERTScore | 用 BERT 上下文向量做软对齐 | 通用生成 | 偏好与参考同风格、同模型族 |
| COMET | 神经模型直接给译文打分 | 机器翻译（当前主流） | 依赖训练数据，难解释 |

### BLEU

**BLEU**（Bilingual Evaluation Understudy）是这一族的祖师爷，1990 年代为机器翻译设计，思想朴素：把模型输出与参考译文在 1~4-gram 上做重叠比对。

```
BLEU = BP * exp( Σ w_n * log p_n )
```

其中 p_n 是各阶 n-gram 精度，w_n 是权重（通常取 1/4 等权），BP 是**长度惩罚（brevity penalty）**——输出过短时把总分压下去，防止「只输出几个高频词就拿满分」。

BLEU 的性质让人又爱又恨：快、不需要训练、不需要人工标注、可批量计算，所以至今仍是 [MachineTranslation](/docs/CS/AI/NLP/MachineTranslation.md) 论文的标配；但它完全不认语义，只要用词与参考不同，哪怕意思分毫不差也照扣分——同义改写是它的头号受害者。

用 BLEU 还有两条纪律：**句级 BLEU 不可信**——参考越少、句子越短，方差越大，论文里有意义的是**语料级聚合**；以及**不同分词、不同参考数量下的 BLEU 互不可比**，把两篇论文的分数直接横比经常是无效对比。

### ROUGE

[Summarization](/docs/CS/AI/NLP/Summarization.md) 的默认指标是 **ROUGE**（Recall-Oriented Understudy for Gisting Evaluation），与 BLEU 构成镜像：BLEU 看精度——生成的词有多少落在参考里；ROUGE 看**召回**——参考里的词有多少被生成覆盖；ROUGE-L 再用最长公共子序列衡量句子级结构对齐。

这个方向差异恰好对应两个任务的焦虑点：翻译怕多说了错话（precision），摘要怕漏掉要点（recall）。同一副软肋也对称存在——ROUGE 偏好长输出与照抄原文，抽取式摘要天然占便宜，生成式摘要稍一改写就被判低分。

变体上，ROUGE-1 / ROUGE-2 数 unigram / bigram 重叠，ROUGE-L 沿最长公共子序列，ROUGE-SU4 引入「跳跃二元组」；不同变体对输出长度与词序的敏感度不同，论文必须写清用了哪一版，否则数字无从比较。

### METEOR and chrF

**METEOR** 是第一个把「与人类判断相关」当作设计目标并写进标题的指标：先做词对齐（对齐时允许同义词与词形变化参与匹配），在精度与召回之间取调和平均，再叠加**碎片惩罚（fragmentation penalty）**，惩罚匹配片段被打乱得七零八落的输出。它比 BLEU 更贴近人类感受，代价是依赖外部词典与更重的工程实现，今天更多作为历史参照与低资源场景的备选。

**chrF** 换了一个维度：把统计粒度从词下沉到字符 n-gram，算字符级 F 值。对土耳其语、芬兰语、匈牙利语这类形态丰富的语言，一个词根可以派生出几十种屈折形式，词级重叠几乎抓不住东西，字符级却依然稳定；对中文这种没有空格、分词方案又彼此不同的语言，字符粒度同样更公平。

### BERTScore and COMET

语义级的两个代表是 **BERTScore** 与 **COMET**。BERTScore 用预训练 BERT 的上下文向量，对候选文本与参考文本的每个词做**贪心匹配**（按向量相似度配对，再聚合成 precision / recall / F 值）——「同义」终于不再被惩罚，与人类判断的相关性显著高于 BLEU 系，而且可以直接用于摘要、对话等「没有唯一标准答案」的任务。它也有自己的偏好：与参考风格接近、与所用 BERT 同族的输出会被略微抬高。

**COMET** 把评估本身变成一个学习任务：输入原文、译文与可选的参考，用专门训练的神经模型**直接回归人类评分**，是当前机器翻译评估的主流与 WMT 比赛的参考指标。代价是它自己也是模型——会继承训练数据中评估者的偏见，也说不清「为什么给这个分」，可解释性远不如 n-gram 指标。

一个实用的组合是「语义指标 + 表层指标」并报：两者都涨通常意味着真实改进，只有一个涨则多半是指标伪影，值得展开看几条具体输出。

### A Worked Example

参考译文是 `the cat sat on the mat` 时，候选 A `the cat is on the mat` 词序动了一处、错了一个词，n-gram 重叠仍然很高；候选 B `a feline rested upon a rug` 意思完全一致，词级重叠却是零。

BLEU 会给 A 高分、给 B 近乎零分；BERTScore 与 COMET 则会给出相反的评价——这个例子就是本篇的核心论点：**每个指标测的是它被设计去测的那个影子，而不是任务本身**。

更隐蔽的一层：BLEU 对词形与分词的依赖意味着，有时「改进」只是换了个分词器。评测报告里不写清预处理细节，可比性就无从谈起。

### Reference-Based and Reference-Free

上面这些指标都要求有参考输出（reference-based）。没有参考时——开放对话、创意写作、代码生成——只剩两条路：参考无关（reference-free）的模型打分（即下文 LLM-as-a-judge），或者人类评估。

翻译与摘要能把自动指标做得这么成熟，本质原因是它们能收集「同一意思的多种标准写法」；任务越开放，可用的廉价指标越少，最终还是要回到人。这也是评估的成本结构：越早期的快速反馈越便宜，越接近上线验收越贵。

### What They Share

这一族的共同结论值得记住：**表层指标与人类判断的相关性有限，句子级尤甚**。指标涨了而译文变差，在这个领域属于常态而非意外——所以翻译的发布验收通常是「BLEU 做快速回归、COMET 做主指标、人类做成对抽检」三者叠加，而不是信任任何单一数字。

### Picking a Metric

面向什么场景选什么指标：研发迭代看便宜、可实时的自动指标（BLEU / chrF / ROUGE），版本验收看学习式指标（BERTScore / COMET）与人类抽检；论文对比则要同时报多个指标，而不是挑对自己有利的那一个。

还有一个容易忽略的维度：**指标要匹配任务**。拿 BLEU 测摘要、拿 ROUGE 测翻译都在文献里出现过，但都是用错影子评错人；摘要真正怕的是捏造（faithfulness），而 ROUGE 完全不测这一点，这是它与人类判断脱节最严重的场景。

另一个经验是**不要把训练目标与验收指标混同**：BLEU 这类可微的奖励信号适合用来微调模型，但把它当最终验收，模型学会的是「像参考」而不是「像人写的」。

## Classification and Tagging Metrics

分类任务的指标看似简单，坑却集中在「平均」这一步。

**precision 与 recall** 的直觉分别是「挑出来的有多少是对的」（查准）与「该挑的挑回来多少」（查全），二者天然互斥：阈值调高，precision 涨、recall 掉。F1 是它们的调和平均，调和而非算术平均意味着**任何一端接近零都会把 F1 拖垮**，这正是想要的惩罚。这组取舍在 [TextClassification](/docs/CS/AI/NLP/TextClassification.md) 的每一个应用场景里都具体存在——垃圾邮件宁可错杀（重 precision），疾病筛查宁可错放（重 recall）。

**accuracy 是类别不平衡下最会骗人的数字**：95% 负类的数据里，全预测为负就有 95% 准确率，却毫无用处。此时应看 **macro 平均**（每类指标等权，少数类与多数类同价，适合关注少数类）还是 **micro 平均**（按样本加权，等同整体准确率，适合关注总量）？经验法则是：**少数类很重要时用 macro，整体吞吐重要时用 micro**，报指标时把两者都写出来最稳。

序列标注（[SequenceTagging](/docs/CS/AI/NLP/SequenceTagging.md)）还多一层粒度问题：**token 级准确率**把每个字都平等对待，而**实体级 F1** 要求边界完全正确才算命中——一个多字实体的边界错一个字，token 级只扣一分，实体级直接判全错。应用真正关心的是「抽出了多少个完整实体」，所以实体级 F1 才是这个任务的收口指标。

**AUC** 一句话：随机取一个正样本与一个负样本，模型给正样本打更高分的概率——与阈值无关，衡量的是排序质量而非某个工作点的表现。

## Retrieval and Ranking Metrics

检索与排序关心「把对的东西排在多靠前」，主流指标有三个：**Recall@k** 看前 k 个结果里召回了多少相关内容；**MRR** 取「第一个相关结果排名」的倒数再平均，适合「找到一个就够」的场景；**nDCG** 按位置做折损累加（越靠前权重越高）并归一化，适合分级相关性与多个结果都重要的场景。这三个指标被搜索、推荐、RAG 的检索端共同使用，展开与变体见 [RecommenderSystem](/docs/CS/RecommenderSystem/RecommenderSystem.md)，本篇不重复。

## Benchmarks

**基准（benchmark）**把多个任务聚合成一个榜单，让「哪个模型更好」有一个公共答案。**GLUE** 是第一代 NLU 基准：把 MNLI、QQP、SST-2 等九项理解任务汇总成一个分数，几年内就因模型逼近人类水平而饱和；**SuperGLUE** 随即用更难的任务顶上，**CLUE** 是它的中文对应物，中文评测与中文模型生态基本围绕它组织。

基准的宿命是一句话：**被解决之日，就是它失效之时**。一旦测试集与排行榜成为目标，动力就会从「提升能力」转向「刷榜」——测试集泄漏、针对性微调、对榜单任务过拟合都会让分数不再代表能力。**BIG-bench** 是另一种思路：用几百个任务（含大量人类也做不好的）专门去测「基准之外」的能力，宁可让分数难看，也要找出饱和基准照不到的盲区。

## LLM-as-a-Judge

生成任务的评估在 LLM 时代有了新工具：**LLM-as-a-judge**——让一个强模型给输出打分或做两两比较，代替（或预筛）人工。规模优势巨大：比人类便宜几个数量级、快得多、并且可以在成对比较上提供稳定的判断。**G-Eval** 让 GPT-4 按评分细则（rubric）逐条打分并借助思维链提升与人类判断的一致性；**MT-Bench** 用多轮问题构造成对比较，证明了强模型裁判与人类偏好有相当高的一致率。

但裁判是模型，模型有自己的偏好。已知的偏差至少三样：**位置偏差**——交换两个答案的顺序，结论可能翻转，靠交换位置取平均来对冲；**长度偏好**——更长的回答更容易被判定更好，即使信息量没有增加；**自我偏好**——裁判偏爱与自己同族模型的输出风格。更根本的是**循环性**：用模型评估模型，评测分布会向裁判的偏好坍缩，模型越像裁判得分越高，而不是越有用。所以人类锚点不可废除——保留一小批人工标注的种子集校准裁判、对裁判的结论做定期抽检，是这套方法能不能用的前提。

## Human Evaluation

绕一圈回到原点：**人类判断是评估的终极目标，所有自动指标都是它的廉价代理**。代理便宜、可复现、可实时监控，但它量的是「与人类的距离」，只有锚在人类身上才有意义。

人类评估的困难同样真实：主观性强（同一段译文，不同评估者可以给出不同的偏好）、评估者间一致性需要度量——**kappa 系数**衡量「剔除随机一致之后，标注者真正一致的程度」，一致性太低意味着任务定义本身就有问题；再加上成本高、不可复现、难以持续运行。工程上的折中是**分层评估**：研发迭代用便宜的自动指标做快速反馈，版本验收用学习式指标（COMET、BERTScore）与人类做（相对可靠的）成对偏好判断，而绝对打分（Likert 量表）因为难以校准，可靠性通常不如成对比较。

评估方案就是项目的**北极星**：它定义了什么叫做「更好」，团队所有的优化都会顺着它爬。能测量才能改进，**测量错了，就改进错了方向**——这是本篇想留给每个 NLP 项目的最后一条。
