## Introduction

信息抽取（information extraction, IE）的目标，是把自然语言文本里的关键事实转成结构化记录——谁对谁做了什么、在何时何地发生。与分词、序列标注这类「理解一句话内部结构」的任务不同，IE 的产物可直接入库、可被查询，因此它天然是知识图谱、搜索引擎与风控系统的上游工序。

IE 传统上被拆成三个递进的层次：先认出文本里提到哪些实体，再判断实体之间存在什么关系，最后把关系聚合成带角色、带时间的完整事件。实体识别即 NER，已在 [SequenceTagging](/docs/CS/AI/NLP/SequenceTagging.md) 中展开；本篇从「实体之后」讲起，主线是关系抽取（relation extraction, RE）与事件抽取（event extraction, EE），并观察这两个任务近年如何被问答化与生成化重新定义。

## The Three-Layer Landscape

三层任务的最小输出单位不同，标注的复杂度与难度也依次抬升：

| 层次 | 输出单位 | 典型表示 | 主要难点 |
| :--- | :--- | :--- | :--- |
| 实体识别 | 文本片段 + 类型 | 人名、机构名、地名 | 边界与类型歧义 |
| 关系抽取 | 二元组 | （头实体, 关系, 尾实体） | 同句多关系、远距离依赖 |
| 事件抽取 | 结构化记录 | 事件类型 + 触发词 + 论元角色 | 跨句论元、schema 复杂 |

三层产物拼装起来就是知识图谱的原料：实体是节点，关系是边，事件则给出带时间、地点与参与者的动态切片。

值得注意的是，三层并非严格串行。事件的论元本身就是实体，事件类型的定义又常引用关系与实体类型；实体链接（entity linking）把抽出的 mention 对齐到知识库中的唯一实体，本质上是检索加消歧，本文不再展开。

正因如此，三层任务共享大量表示与标注基础设施——一个编码器、一套实体体系可以同时服务多个层次，这为后文「联合抽取」的动机埋下了伏笔。

## Relation Extraction

解决完「有哪些实体」，「实体之后」的第一个问题是：这两个实体之间是什么关系？

### Supervised Relation Classification

句子级的关系分类把问题形式化为：给定一个句子与其中两个已标注实体，从预定义的关系集合（外加一个 no_relation）中选一个标签。设定简单可控，几十年的方法演进基本围绕一件事展开——怎么把实体在句中的位置信息表达给分类器。

先要意识到，关系体系本身是数据集定义的：不同语料各有一套标签表，模型学到的只是标签编号的映射，并不真正理解「出生地」与「任职于」的语义差别。这种「标签无语义」的设定，日后正是 prompt 范式试图撬动的地方。

早期方法依赖特征工程：词法特征、实体类型、上下文窗口，以及依存句法路径等人工特征，配合最大熵或 SVM。人工特征的覆盖面决定模型上限，而特征又高度依赖句法工具的准确率。

深度学习时代先用 CNN，关键改动是引入位置特征（position embeddings），把每个词到两个实体的相对距离编码成向量拼进词表示，让卷积核能感知词是靠近头实体还是尾实体。

PCNN 进一步按两个实体的位置把卷积输出分段池化，压低句子其余部分对关系判别的干扰。预训练模型到来后，做法简化为把两个实体用标记符（如 [E1] / [E2]）包起来送入 BERT 或同类编码器，再接一个分类头——其「两段文本联合编码」的结构与 [SemanticMatching](/docs/CS/AI/NLP/SemanticMatching.md) 中同源，只是监督信号落在关系标签上。

### Distant Supervision

监督式 RE 的瓶颈在标注：句级关系标注要求标记者同时理解实体与关系语义，成本极高。远程监督（distant supervision）用一个绕行办法打开局面——拿已有知识库里的三元组，把同时提到这两个实体的句子自动回标为对应关系。数据规模由此从数万句放大到百万级，代价是把噪声也一并放大。

问题出在假设本身：「句子含头尾实体」并不等于句子表达了该关系（可能只是巧合共现），而一个句子又常被多个三元组同时回标，假阳性因此大量存在。

处理噪声的演化铺出了多示例学习的整条路线：把回标到同一三元组的句子视为一个包（bag），在包级而非句级做预测；再用注意力机制对包内句子加权（attention over instances），让模型自行压低噪声句的权重。

还要看到，回标数据天然覆盖不到未入知识库的关系，长尾与新兴关系在训练集中缺席。这也是后来少样本与开放域抽取方向兴起的动机之一。

### Few-shot and Prompt-based RE

少样本方向解决的是新关系类型的冷启动：每种新关系只给几个样例，靠原型网络或元学习从已有关系上迁移能力，把「学到关系的语义」与「记住标签编号」分开对待。

更晚近的 prompt 范式把分类任务整个重写——把句子与关系描述填进模板，让预训练模型补全「[头实体] 与 [尾实体] 的关系是 [MASK]」，关系标签退化成一个待生成的词（verbalizer）。

任务形式换了几轮，目标始终是同一张关系分类表；变化的是「关系语义」在哪里被表达——从标签编号，到样例分布，再到自然语言的模板描述。

## Joint Extraction

### Joint Tagging Schemes

先跑 NER 再对识别结果做关系分类，误差会逐级传播：实体边界错一个词，关系判定可能整个作废。

更隐蔽的损失是信息流断头：关系模型只看得到实体识别的输出，看不到它的不确定性，也无法把「这里有哪些关系」的线索回传给实体识别。

联合抽取把两个子任务放进一个模型，让实体与关系的监督信号互相约束。最直接的方案是联合标注：为每个 token 设计同时编码实体角色与关系类型的复合标签，一张标签序列同时解出实体与它们之间的三元组。

方案优雅，代价是标签空间随关系数膨胀，且一个 token 参与多个关系的重叠三元组无法表达——标签体系一旦成型，任务的天花板也就此划定。

### Cascade Binary Tagging

CasRel 换了个拆法：把三元组展开成两步二元判断，先抽出头实体（subject），再对每一种关系单独回答「这个头实体在句中有没有对应的尾实体、是哪一个」（relation-specific object tagging）。

产出结构因此成为「头实体 → 一组关系 → 每组关系下的尾实体集合」。因为每种关系独立标注，重叠三元组天然可表达。

共享编码器又让实体与关系的表示互相滋养，头实体识别的质量直接决定后续关系判定的上限。把 n 元的整体决策拆成一组二元决策，这是任务重构的一个代表性案例。

### Generative Triples

大模型时代出现了更激进的重构：把 schema（关系类型清单）写进提示词，让模型直接生成三元组文本，或按「头实体 | 关系 | 尾实体」的格式逐行输出。

结构预测被还原成条件文本生成，约束从解码结构转移到提示设计与后处理校验上。生成式方案在开放域与零样本场景表现亮眼，但输出格式的稳定性、穷尽性与幻觉控制仍是工程上的主要摩擦点。

## Event Extraction

### Anatomy of an Event

事件抽取的对象比关系更复杂。一条事件记录包含事件类型（如「袭击」「死亡」）、触发词（trigger，文本中最能标志事件发生的词，常为动词或名词），以及若干论元（argument）——参与者、时间、地点等实体。

每个论元在事件中承担特定角色（role，如「受害者」「发生地点」）。ACE 系列语料把各类事件预定义为 schema，规定每种事件有哪些角色、角色允许什么实体类型，是这一任务事实上的基准数据来源。

### From Classification to QA

早期方法是分类式的：先对每个 token 做触发词分类以判定事件类型，再在触发词所在句子内对候选实体做论元角色分类。

两个阶段都是分类器，因此同样有流水线误差，也受制于「论元必须与触发词同句」的假设——而这恰恰是真实文本最不成立的假设。

把事件抽取重构成问答（event extraction as question answering）改变了这一切：对每种「事件类型 × 角色」的组合自动生成问句，如「谁被袭击了？」「事件发生在哪里？」，再让阅读理解模型去原文中找答案片段。

转换带来几个结构性好处——所有事件类型共享同一套问答参数；「没有该论元」有了自然处理方式（答不出即判空）；问答模型跨句、跨段的阅读能力也被顺势引入。

文档级事件抽取正需要这一点：真实报道里触发词与论元常常分布在不同句子，时间、地点甚至可能只在标题里出现，整篇文档才是完整事件的展开单位。

## The Drift of Task Boundaries

把生成式三元组与事件问答化放在一起看，同一个趋势便浮出水面：抽取任务正在被两种重构吞并。

| 重构 | 代表形态 | 结构化预测变成 | 主要收益 |
| :--- | :--- | :--- | :--- |
| 问答化 | 事件抽取 as QA | 阅读理解（在文本中找答案） | 跨类型共享参数、天然处理空论元 |
| 生成化 | LLM 直接输出三元组 | 条件文本生成 | 零样本、适配开放 schema |

两者方向相反——一个把结构问题化为语言理解，一个化为语言生成——却都在剥同一层东西：任务专属的标签体系与解码器。

对从业者的现实含义是任务边界在模糊化：一个「关系抽取」需求，最终可能由通用 [QuestionAnswering](/docs/CS/AI/NLP/QuestionAnswering.md) 流水线或 [LLM](/docs/CS/AI/LLM/LLM.md) 的部署方案承接，专用模型的价值逐渐收窄到高吞吐、强 schema 约束与可解释性这些维度上。评估时必须确认对比双方用的是同一套任务定义，否则数字之间不可比。

## Evaluation

抽取任务的标准评测都是精确匹配下的 F1：实体级按片段与类型完全匹配统计，关系级按三元组匹配，事件级则把触发词识别与论元角色填充分成两级分别报告。

此外要留意部分匹配口径与严格口径的差别——后者要求论元边界与类型同时正确，分数通常显著更低，引用他人数字前先确认口径。更细的评估方法在 [Evaluation](/docs/CS/AI/NLP/Evaluation.md) 已有展开，这里只强调远程监督数据的一个陷阱。

远程监督构建的数据集，测试集往往也是自动回标生成的，混入的噪声标注会让模型的正确预测被判为错误，于是 F1 存在一个不为 100% 的「标注上限」，且不同数据集的噪声率各不相同。

跨数据集直接比较分数因此意义有限：报告结果时，说明数据来源与评测口径比分数本身更重要。

## IE as the Gateway to Structured Data

从一条句子到一个可查询的三元组，信息抽取扮演的是「结构化世界的入口」：搜索的实体卡片与知识面板依赖它提供事实，风控从合同与新闻中识别可疑的关联方与交易，情报分析则把零散报道拼成事件脉络。

也正因为它处在这样一个咽喉位置，任务定义上的每一次重构——从联合标注到问答化、生成化——都会迅速传导到下游应用的架构选择上。理解 RE 与 EE 这几十年的方法进退，本质上是在理解「机器如何把语言兑换成数据」这件事本身。
