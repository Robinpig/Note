## Introduction

分词（tokenization）是 NLP 流水线的第一道工序：把原始文本切成模型能处理的**词元（token）序列**，再映射为词表里的整数 ID。它看起来只是预处理，实际上划定了后面所有环节的信息边界——单位切错了，表示、标注、生成统统建在错误的粒度上。

它的难处分两层。第一层是「词」这个单位本身没有清晰定义：什么算一个词，多数语言给不出明确答案，只能由模型裁决，中文这类无空格语言表现得最极端。

第二层是词表的封闭性与语言的开放性之间的矛盾：无论词典多大，新词、专名、拼写变体总会落在词表之外。前者带出中文分词与序列标注，后者带出子词（subword）切分；两条线最终又在 LLM 的 tokenizer 里合流——在那里，分词直接对应计费口径与上下文预算。

本篇按这条演进线展开：先看切分为什么是难题，再看中文分词三代方法如何递进，然后对比三种子词算法与 SentencePiece 的工程意义，最后落到 LLM 时代 tokenizer 的现实影响。

## Why Segmentation Is Hard

英文看似有免费答案：空格已经把句子切好了。但边界情况很多——「don't」该切成「do」与「n't」两个单位，还是保留整词？「U.S.」里的点算不算边界？连字符复合词、「New York」这类固定搭配呢？空格给出的只是默认答案，不是正确答案。

中文更极端：书面语没有词间空格，「南京市长江大桥」究竟切成「南京市 / 长江大桥」还是「南京 / 市长 / 江大桥」，只能由模型裁决；「乒乓球拍卖完了」既能切成「乒乓球 / 拍卖 / 完了」（在说拍卖），也能切成「乒乓球拍 / 卖完了」（在说球拍售罄）。两种切法都语法通顺，选错直接改变句义。

第三类是形态丰富的语言：俄语、芬兰语、土耳其语的一个词根能衍生出几十种屈折形式，按整词建表会让词表爆炸，而每种形式在语料里的出现次数都很低，OOV 与数据稀疏问题同时爆发。

还有一层常被忽略：**粒度本身就不唯一**。「中华人民共和国」是一个词还是四个词，取决于任务——检索系统希望切得细，句法分析希望保留整体，语音合成又另有标准。切分没有「客观正确」的答案，只有「对当前任务合适」的答案。

这三类困难的共同后果是：分词错误会沿流水线传播——切错的边界变成下游标注的错误特征，而且很难在后续阶段修复。这就是为什么说分词是建模问题，而不是查表问题。

## Chinese Word Segmentation

中文分词的方法史大致翻了三代，每一代都在修正上一代的失败模式。还应该知道一个背景：中文分词连标准都不唯一，PKU、MSR 等语料库的切分规范并不一致，评测首先遭遇的是「标准之争」——更完整的语境（评测、简繁、字词粒度之争）见 [ChineseNLP](/docs/CS/AI/NLP/ChineseNLP.md)。

### Dictionary and Rule-Based Matching

第一代是词典加规则。前向最大匹配从左到右贪心取最长词，逆向最大匹配从右往左做同样的事；后者在多数语料上错误更少——句子的核心成分往往偏后，从右往左先锁定它更容易。更精细的做法是**最短路径**：把一句话所有可能的词构造成有向无环图（DAG），每条边用词频加权，再求一条最优路径——jieba 的分词主干正是这条路。

贪心的失败很直观：「研究生命起源」里，前向最大匹配看到「研究生」就吞了下去，切出「研究生 / 命 / 起源」；正确切法「研究 / 生命 / 起源」要求模型先放弃眼前最长的词，才能拿到全局更优的分割。最短路径缓解了这类问题，但代价是仍然假设「词表里的词才对」。

词典方法有两个结构性缺陷。一是**新词**：网络用语、专有名词、品牌名在词表里根本没有。二是**歧义**：「南京市长江大桥」的所有候选切分在词表里都合法，靠词频也未必选得对。要突破这两点，必须跳出「维护词典」的思路。

### Segmentation as Sequence Labeling

第二代做了一次关键的角色转换：不再问「哪些字组成一个词」，而是**给每个字打标签**——B（词首）、M（词中）、E（词尾）、S（单字词），相邻标签的组合自然还原出切分边界。于是分词变成了标准的序列标注（sequence labeling）问题：HMM 用状态转移与发射概率解码，CRF 再进一步，以全局归一化与任意上下文特征取代 HMM 的独立性假设。

这次范式转换的意义大于精度提升本身：「维护词典」变成「训练模型」，领域词典与新词发现都能以特征或训练数据的形式融入统一框架；而且未登录词也有了出路——在标签转移的约束下，没见过的字词组合也能由周围上下文切出合理边界。标注体系、解码算法与实体级评估的通用形态，见 [SequenceTagging](/docs/CS/AI/NLP/SequenceTagging.md)。

### Neural Sequence Labeling

第三代把手工特征也交给网络：BiLSTM-CRF 用双向 LSTM 自动学习上下文表示，CRF 层只负责约束标签之间的合法转移，在多个中文分词基准上明显超越统计方法。再往后，基于 [Transformer](/docs/CS/AI/Transformer.md) 的 BERT 直接在预训练表示上接一个标注头，靠语料规模继续拉开差距。

有意思的是，到了预训练时代，「分词」一词的含义开始漂移：当模型本身以子词为单位训练时，传统意义上的词切分不再是必经之路——子词切分同时承担了分词与表示两件事。这正是下一节要展开的问题。

## Subword Segmentation

### The Open Vocabulary Problem

语言永远走在词典前面：新词、拼写错误、专有名词、emoji、罕见姓氏，总会落在词表之外。按整词建模时，OOV 词只能塌缩成一个 UNK 符号，信息直接丢失；反过来按字符建模，虽无 OOV，代价是序列变长、语义粒度太细——模型很难从孤立的字里看出「心脏移植」是一个整体概念。

子词切分是这场折中的产物：**高频词保持整词，低频词拆成有意义的片段**。「tokenization」变成「token / ization」，「unbelievable」变成「un / believ / able」，词表大小与序列长度同时可控。这也埋下一个绕不开的**三角权衡**——词表大小、序列长度、语义粒度，三者最多取其二，后文还会回到它。

子词不只服务于切分，也服务于表示：fastText 用字符 n-gram 构造词向量，把前缀、后缀、词根这些词形信息直接编码进表示，形态丰富语言与 OOV 词的向量质量因此明显改善。

### BPE, WordPiece, and Unigram

三种主流算法在「从哪里出发、往哪个方向走」上彼此不同：

| 算法 | 方向 | 合并 / 裁剪准则 | 代表 |
| :--- | :--- | :--- | :--- |
| BPE | 自底向上合并 | 频率最高的相邻符号对 | 早期 NMT、GPT 系 |
| WordPiece | 自底向上合并 | 使语言模型似然增益最大的对 | BERT |
| Unigram | 自顶向下裁剪 | 删掉后似然损失最小的子词 | SentencePiece 默认 |

**BPE（字节对编码，Byte Pair Encoding）**从单个字符出发，反复统计语料中相邻符号对的频率，把最高频的一对合并成新符号，重复固定次数即得到词表。以 lowest 为例：如果其中字母组合出现得足够频繁，「est」会被合并出来，最终词被切成「low / est」；合并轮数就是控制词表大小的旋钮。它原本是数据压缩算法，2016 年被借来解决翻译中的 OOV，从此成为事实标准。训练结束后，切分只需按学到的合并顺序执行，确定性、可复现——这是它适合大规模在线服务的重要原因。

**WordPiece** 同样自底向上，但选择准则从频率换成**似然增益**：合并哪一对能让语料的语言模型似然提升最大就选哪一对，对低频但有语言意义的组合更敏感（BERT 的词表用它，非词首片段会带一个「##」前缀）。**Unigram** 方向相反，自顶向下：先准备一个足够大的候选子词词表，用 EM 估计每个子词的概率，再按「删掉后损失最小」逐轮裁剪到目标大小，推理时用维特比算法选出概率最大的切分；每个候选子词都有概率这一点，也为后面的采样式正则化提供了基础。

三者产出的切分在多数句子上相似，分歧集中在低频词与歧义边界；工程上与其纠结算法，不如认真设定训练语料与词表大小。

### SentencePiece and Subword Regularization

SentencePiece 的贡献在工程层面：它**直接在原始文本上操作**，把句子当作 Unicode 字符序列，不依赖任何语言相关的预分词（英文按空格切、中文按字切这类前置步骤），连空格本身也被编码成一个特殊符号（▁，SentencePiece 的标志性设计）。于是它语言无关、可逆（解码能一字不差还原原文，包括空格），无空格语言与多语言语料可以共用一套流程——中文、日文、泰文的使用者不必再为预分词写语言特定的规则。T5 等多语言模型与许多中文模型的词表，都是这样训练出来的。

它还有两个常用旋钮：词表大小（vocab_size）与字符覆盖率（character_coverage）——后者控制词表需要覆盖语料中多大比例的不同字符，直接决定罕见文字是被整体保留还是拆碎。

配套的 **Subword Regularization** 解决另一个问题：确定性切分只有一个答案，模型会把答案连同其噪声一起记住。训练时按 Unigram 概率**采样多种切分**（同一句话每次切法可能不同），迫使模型对切分方式不敏感，在低资源与形态丰富语言的翻译上带来稳定增益。它揭示的观点更一般：分词不必唯一——切分本身可以是可随机化的数据增强。

### Byte-Level BPE

再往前一步，是把基本单元直接降到**字节**：BBPE（Byte-Level BPE）以 256 个字节值作为初始符号，任何 Unicode 文本先转成 UTF-8 字节序列再合并。收益是彻底的：**OOV 在物理层面不再存在**，emoji、罕见汉字、任意符号都有字节表示。代价也同样清楚：一个汉字在 UTF-8 里占三个字节，字节级词表下中文序列天然比英文长，同样的语义要消耗更多位置与注意力。BBPE 由 GPT-2 引入并被后续生成模型广泛采用，它也是「中文比英文费 token」这个直觉的直接根源。

## Tokenizers in the LLM Era

今天绝大多数 LLM 的 tokenizer 都是 BPE 家族的工程实现。GPT 系模型使用 tiktoken 这组高性能 BPE 工具：词表随代际演进，从 cl100k_base 走向 o200k_base，规模更大、覆盖更宽，同样的文本切出的 token 更少、序列更短。

开源与闭源模型的词表路线高度趋同：面向生成的模型几乎都采用字节级 BPE 的不同变体，差异主要在训练语料配比、词表规模与细节实现；而带「##」前缀的 WordPiece 更多留在 BERT 时代的编码器里。

词表规模的演进也值得一提：BERT 时代词表约三万，GPT 系最初约五万，到 o200k_base 已接近二十万——词表越滚越大，背后正是三角权衡在随模型规模与多语言需求移动。

### Vocabulary Design and Chinese

词表里中文的覆盖程度，直接决定中文的成本。字节级词表下，一个汉字通常占 1 到 2 个 token，具体取决于该字的常见程度——常用字可以是一个 token，生僻字会被拆成两三个字节级 token；而中文词表占比高的模型（Qwen、DeepSeek 系）常把高频汉字与常用词整体收进词表，同一段中文的 token 数明显少于英文中心词表的模型。这不是细节：**token 数既是计费口径，也是上下文预算**，tokenizer 效率的差异会被放大为费用与可用上下文长度的双重差异（调用与预算的接口视角见 [LLM](/docs/CS/AI/LLM/LLM.md)）。

词表还带来一个结构性后果：它是模型的「文件格式」。不同 tokenizer 的模型无法直接共享输入输出层，模型合并、蒸馏、词表扩展等操作都要先解决 token 对齐——分词选型是一件一旦定型就很难反悔的决策。

### Tools

实用层面，中文分词仍有成熟选择：

- **jieba**：使用最广，DAG 加 HMM、接口极简；但版本停在 0.42.1、2020 年后未再发版，新项目需要评估维护风险。
- **HanLP 2.x**：活跃维护，走多任务预训练模型路线，分词、词性、NER 一套覆盖。
- **pkuseg / LAC / THULAC**：出自学术团队，精度各有侧重，但维护明显放缓。
- **tiktoken / SentencePiece**：面向 LLM 词表训练与编码的库，服务于「给模型造 tokenizer」而非语言学意义上的分词，两者常配合使用。

完整对照与选型建议见 [Tools](/docs/CS/AI/NLP/Tools.md)。

## The Tradeoff Triangle

回到开头那个三角：更大的词表让序列更短、注意力开销更小，但嵌入矩阵与输出 softmax 更大、低频条目训练不足；更小的词表让模型紧凑，却让每句话更长、长文档更早撞上上下文上限。词表大小、序列长度、语义粒度，没有免费的第三边。

分词是 NLP 的第一道工序，也是最容易被低估的一步——它选的不是算法，而是模型看待语言的单位。中文分词的三代演进回答「怎么切」，子词算法回答「以什么为切分单位」，LLM 时代的 tokenizer 则把这两个问题统一成工程与成本问题：切得好不好，最终会落在账单和上下文预算上。
