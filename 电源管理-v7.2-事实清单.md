### 1.11 PM QoS 延迟约束（替代已删除的 sysfs latency_limit）[源码确认]

```c
s64 cpuidle_governor_latency_req(unsigned int cpu)
{
	struct device *device = get_cpu_device(cpu);
	int device_req = dev_pm_qos_raw_resume_latency(device);
	int global_req = cpu_latency_qos_limit();
	int global_wake_req = cpu_wakeup_latency_qos_limit();
	if (global_req > global_wake_req)  global_req = global_wake_req;
	if (device_req > global_req)       device_req = global_req;
	return (s64)device_req * NSEC_PER_USEC;
}
```

### 1.13 menu governor [源码确认] `drivers/cpuidle/governors/menu.c`（544 行）

**常量**（`menu.c:22-27`）：
```c

#define INTERVALS (1UL << INTERVAL_SHIFT)      /* = 8 */

```
**问题中提到的 `NR_CPUS` 在 v7.2 menu.c 中不存在。** 也没有"目标补齐/降幅的百分比常量"——预测用 `correction_factor[6]`（每桶一个 running average），衰减是 `new_factor -= new_factor / DECAY`（`menu.c:479`），即 1/8 衰减。

**来自 `governors/gov.h`（19 行）的常量**：
```c

#define SAFE_TIMER_RANGE_NS	(2 * TICK_NSEC)
```

**per-CPU 结构 `struct menu_device`**（`menu.c:70-79`）：`needs_update`、`tick_wakeup`、`next_timer_ns`、`bucket`、`correction_factor[BUCKETS]`、`intervals[INTERVALS]`、`interval_ptr`。实例：`static DEFINE_PER_CPU(struct menu_device, menu_devices);`（`menu.c:98`）。

**分桶阈值 `which_bucket()`**（`menu.c:81-96`）——这是"理想值计算里的除数"对应的分桶逻辑：
```c
duration_ns < 10us   → 0
duration_ns < 100us  → 1
duration_ns < 1000us → 2
duration_ns < 10000us→ 3
duration_ns < 100000us→4
else                 → 5
```

**预测算法入口 `menu_select()`**（`menu.c:218-394`）：
1. `latency_req = cpuidle_governor_latency_req(dev->cpu)`（:222）
2. `data->needs_update` → 调 `menu_update()`（:227-229）；否则若 `!dev->last_residency_ns`（上次被驱动拒绝）→ `menu_update_intervals(data, UINT_MAX)`（:237）
3. `predicted_ns = get_typical_interval(data) * NSEC_PER_USEC`（:241）
4. 若 `predicted_ns > RESIDENCY_THRESHOLD_NS || tick_nohz_tick_stopped()`（:242）：
   - `delta = tick_nohz_get_sleep_length(&delta_tick)`（:246）
   - `timer_us = div_u64((RESOLUTION * DECAY * NSEC_PER_USEC) / 2 + data->next_timer_ns * data->correction_factor[bucket], RESOLUTION * DECAY * NSEC_PER_USEC)`（:256-259）— 注释："Round up the result for half microseconds."
   - `predicted_ns = min(timer_us * NSEC_PER_USEC, predicted_ns)`（:261）
   - 若 `tick_nohz_tick_stopped() && predicted_ns < TICK_NSEC && next_timer_ns > SAFE_TIMER_RANGE_NS` → `predicted_ns = next_timer_ns`（:272-274）
5. else 分支（:282-284）：`next_timer_ns = KTIME_MAX`，`delta_tick = TICK_NSEC / 2`，`bucket = BUCKETS - 1`

**`menu_select` 早退条件**（:287-298）：若 `latency_req == 0` 或（`next_timer_ns < states[1].target_residency_ns || latency_req < states[1].exit_latency_ns`）且 state[0] 未禁用 → `*stop_tick = !(states[0].flags & CPUIDLE_FLAG_POLLING); return 0;`

**主循环**（:305-362）核心判定：
- `dev->states_usage[i].disable` → skip
- 首个可用状态赋 `idx = i`
- `s->exit_latency_ns > latency_req` → `break`
- `s->target_residency_ns <= predicted_ns` → `idx = i; continue;`
- POLLING 逃生口（:328-335）：若当前 idx 是 polling 态，且候选 `target_residency_ns < RESIDENCY_THRESHOLD_NS`、`target_residency_ns <= next_timer_ns`、`exit_latency_ns <= predicted_ns` → 改用物理态，`predicted_ns = s->target_residency_ns`
- `predicted_ns < TICK_NSEC` → `break`
- tick 未停且当前态浅 → `predicted_ns = states[idx].target_residency_ns; break`
- tick 已停：`if (states[idx].target_residency_ns < TICK_NSEC && s->target_residency_ns <= delta_tick) idx = i;` 后 `return idx`
- 末尾（:371-391）：`(POLLING || predicted_ns < TICK_NSEC) && !tick_nohz_tick_stopped()` → `*stop_tick = false`，并可能向下修正 idx

**`get_typical_interval()`**（`menu.c:116-210`）判定要点：
- 采样丢弃 `value <= min_thresh || value >= max_thresh`
- 若 `divisor == INTERVALS` 用 `>>= INTERVAL_SHIFT`，否则 `do_div(avg, divisor)`
- 接受条件（:177-181）：`avg_sq > variance * 36 && divisor * 4 >= INTERVALS * 3`（即 avg > 6*stddev）**或** `variance <= 400`（stddev ≤ 20 us）
- 离群剔除：若 `divisor * 4 <= INTERVALS * 3` 直接 `return UINT_MAX`（允许最深态）；否则按 `avg - min > max - avg` 收紧阈值后 `goto again`
- guard：`if (likely(variance <= U64_MAX/36))`（:177）

**`menu_update()`**（`menu.c:418-503`）：
- `data->tick_wakeup && data->next_timer_ns > TICK_NSEC` → `measured_ns = 9 * MAX_INTERESTING / 10`（:451）
- POLLING 态因超时退出 → `measured_ns = data->next_timer_ns`（:461）
- 否则 `measured_ns = dev->last_residency_ns`；`> 2 * target->exit_latency_ns` 则减去 exit_latency，否则 `measured_ns /= 2`（:467-470）
- `measured_ns > next_timer_ns` → 夹住（:474）
- 系数更新：`new_factor = correction_factor[bucket]; new_factor -= new_factor / DECAY;` 然后 `new_factor += div64_u64(RESOLUTION * measured_ns, next_timer_ns)`，若 `next_timer_ns == 0 || measured_ns >= MAX_INTERESTING` 则 `new_factor += RESOLUTION`（:478-489）

**`menu_reflect()`**（`menu.c:404-411`）：`dev->last_state_idx = index; data->needs_update = 1; data->tick_wakeup = tick_nohz_idle_got_tick();`

**注册**（`menu.c:528-544`）：`.name = "menu"`、`.rating = 20`、`postcore_initcall(init_menu)`
